# G studio 0.9

轻量原生 Android AI 聊天客户端，可配置自己的中转站或自建模型服务。应用名称为 **G studio**，包名为 `cn.g.studio`，最低 Android 8.0（API 26）。它是独立应用，不修改 G music、G space 或它们的签名。

## 安装与开始聊天

安装包：`~/G-studio-0.9.apk`。在 Termux 中复制到下载目录后，使用文件管理器打开：

```sh
cp ~/G-studio-0.9.apk ~/storage/downloads/
```

0.9 与 0.1～0.8 使用相同包名和签名，可以直接覆盖安装，保留服务配置、密钥和聊天记录。

打开应用，点击“添加服务”，或从左上角菜单进入“API 服务 → + 添加 API 服务”。填写服务名称、API 地址、API Key 和模型 ID；可点击“获取模型列表”选择模型。最后点击“保存并使用”。模型列表接口不可用时，可以手动填写服务商提供的模型 ID。

地址示例（占位域名，不是已配置服务）：

- `https://example.com` → 自动使用 `https://example.com/v1/chat/completions`。
- `https://example.com/v1` → 使用该版本前缀。
- `https://example.com/custom/v1` → 保留自定义路径前缀。
- `https://example.com/v1/chat/completions` → 也可以直接粘贴完整聊天接口地址。

聊天使用 `POST /chat/completions`，模型列表使用 `GET /models`，鉴权使用 `Authorization: Bearer ...`。服务必须兼容这些接口，不是把任意网站地址填进来就能聊天。API Key 可以留空，供不要求鉴权的自建服务使用。

协议参考：[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)。

## 文生图与文生视频

从左侧菜单进入“生图与视频”，或点击输入框旁的 ＋，选择“AI 生图 / AI 视频”。进入创作页后，选择 API 服务与生图/视频模型 ID，输入画面描述，再点击生成。尺寸、质量和秒数留空时使用服务默认值；填写时须符合对应模型支持的参数。

API 服务编辑页包含生图模型、视频模型、Images / Responses / 视频三个接口路径、可选图片工具模型和“视频使用 JSON 提交”选项。只提供生成服务的配置可以不填聊天模型。模型 ID 由服务商提供，也可以在创作页获取模型列表后选择。

- 生图：支持 Images 直接生图和 Responses 工具生图。在创作页的“调用方式”底部面板中选择。自动模式对 `gpt-6.1-sol` 使用 `POST /responses`，发送原样主模型 ID、`input`、`tools: [{type: "image_generation"}]` 与强制图片工具选择；尺寸、质量放在工具参数中，读取 `output[].image_generation_call.result` 的 base64 图片。工具模型可在服务编辑页选填，默认由服务决定，不能把主模型 ID 当作图片工具模型。其他模型在自动模式下使用 Images；如服务商使用别名，可手动选择 Responses。
- Images：标准 `POST /images/generations` JSON 请求，发送 `model`、`prompt`，可选 `size` 与 `quality`。接收 `data[].b64_json` 或 `data[].url`，保留生成图片的原始字节并缓存在本机，支持图片预览与保存。
- 视频：标准 `POST /videos`，默认 multipart，也可按服务要求启用 JSON。提交后使用 `GET /videos/{id}` 查询进度，完成后使用 `GET /videos/{id}/content` 下载 MP4；兼容已完成任务返回的 `url` / `video_url`。支持应用内预览与保存。
- 接口路径接在 API 前缀后。例如 API 地址为 `https://example.com/v1`、生图路径为 `/images/generations` 时，访问 `https://example.com/v1/images/generations`。自定义路径仍须使用这里描述的请求和任务结构。

协议参考：[Responses 生图工具](https://developers.openai.com/api/docs/guides/tools-image-generation)、[GPT-6.1 Sol 工具支持](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[OpenAI Docs 生图接口](https://developers.openai.com/api/reference/resources/images/methods/generate)、[视频提交接口](https://developers.openai.com/api/reference/resources/videos/methods/create)、[视频生成与下载](https://developers.openai.com/api/docs/guides/video-generation)。

“暂停等待”只停止本机请求与等待，不会取消服务器已接受的任务。任务 ID、状态与已收到的图片结果会保存在本机；之后点击“继续查询 / 保存”使用已有任务或缓存，不会自动重新提交生成请求。提交超时且尚未获得任务 ID / 结果时，会显示“提交结果未确认”，需要先在服务商处核对，重新点击生成会创建新任务。

视频每五秒查询一次，单次最多自动等待约十分钟，之后可以继续查询。图片结果收到后先缓存再检查暂停状态，避免暂停时丢弃已收到的结果；下载失败可从缓存继续；成功后清理临时的 base64 结果。单张图片最多 20 MB，视频最多 256 MB。部分服务的结果有有效期，请及时保存到设备。创作页展示任务记录，点击“保存到设备”后选择目标位置；删除记录会删除本机缓存，不会取消远端任务。

生成接口取决于服务商权限和模型能力。普通聊天接口或视觉聊天模型不代表支持生图或视频。当前只实现上述标准协议的文字生成入口，不包含原生 Gemini、Kling、可灵、Seedance 等专用协议、参考图生成、视频续接或聊天模型自动调用创作工具；这些需要按服务商接口文档适配。

## 侧边菜单

点击左上角菜单按钮，侧栏会从左边滑入，并显示背景遮罩。也可以从屏幕左侧边缘向右拖出；向左拖动侧栏、点击右侧遮罩、点击收起按钮或按系统返回键，都可以收起菜单。拖动距离与速度决定松手后展开或收起，菜单内容支持上下滚动。

侧栏包含新对话、生图与视频、API 服务、记忆和最近会话。打开侧栏前保存当前草稿，刚输入而尚未发送的对话也会列出。已删除独立“会话记录”页和“导出当前对话”功能；会话统一在侧栏显示，每次展示 20 段，可加载更多，点击继续聊天，长按重命名或删除。旋转屏幕后保留展开状态。应用生成回复期间可以打开菜单查看；切换会话和服务仍需先停止生成。

使用 Android 全面屏返回手势时，应用为屏幕左侧中部预留了拖出菜单的区域；可以优先从左侧中部开始滑动。侧栏展开时，聊天内容不会接收遮罩下的点击。

## 底部面板

附件加号会展开从屏幕底部滑入的面板，显示“图片”和“文件”两张卡片。点击卡片后，面板先收起，再打开系统选择器。可以向下拖动顶部把手、点击遮罩、点击收起按钮或按系统返回键收起面板。附件面板的展开状态支持旋转后恢复。

消息操作、服务选择、模型搜索、思考内容、附件预览、重命名与删除确认也统一使用底部面板，应用内已移除居中的 AlertDialog。长内容支持滚动，模型列表和搜索使用可伸缩布局。系统文件选择仍使用设备提供的界面。

后续应用内的选择、操作、确认与预览继续复用这套底部面板；项目约定记录在 `AGENTS.md` 中。

## 图片与文件附件

点击输入框左边的 **＋ → 图片 / 文件**，在系统文件选择器中选取一个或多个文件。附件会先复制到应用私有目录，显示在输入框上方；点击名称可查看图片或文字预览，点击 × 可以移除。PDF 显示文件信息。然后填写问题并发送，也可以只发送附件。

- 图片：可读取的 JPG、PNG、WebP 等静态图片，自动校正方向并转为 JPEG，去除元数据；长边最多 2048 像素，压缩后最大 2 MB。原始图片最大 20 MB。透明背景会变为白色，动图只取一帧。
- 文本：TXT、Markdown、CSV、JSON、代码等，读取为文字加入对话；支持 UTF-8、带 BOM 的 UTF-16 和 GB18030。文件最大 1 MB，最多 12 万字符，不会悄悄截断正文。
- DOCX：最大 8 MB，提取文档正文文字与基本段落。图片、复杂排版、页眉页脚和批注不包含在提取结果中，文档最多 12 万字符。
- PDF：最大 8 MB，按 Chat Completions 的 `file` 内容部分随请求发送，需要中转站和所选模型支持 PDF 输入。图片同样需要视觉模型。文本和 DOCX 以普通文字发送，兼容普通文字聊天模型。

每条消息最多 6 个附件，附件文件合计最多 12 MB；所携带上下文的附件内容也有总量限制，超出时会提示减少上下文轮数或新开对话。旧版 DOC、Excel、PPT、压缩包、音视频等暂不支持，可以先转换为 PDF 或文本。

图片与 PDF 直接放入发往所配置 API 的请求，无需另建图床或先上传到另外的平台。附件仅在点击发送后随对话请求发出。发送后附件仍保存在本机，恢复会话、继续追问和重新生成时可以继续使用。删除会话或移除未发送附件会回收不再需要的文件。

附件协议依据 OpenAI Docs 的[图片输入](https://developers.openai.com/api/docs/guides/images-vision)和[文件输入](https://developers.openai.com/api/docs/guides/file-inputs)。第三方中转站是否支持相同能力，需要按实际服务验证。

## 已有功能

- 多个 API 服务的添加、编辑、删除与切换；模型 ID 可手动填写或获取、搜索。

- 简单 Markdown 显示和复制。

## 长期记忆

从侧栏“记忆”进入管理页，手动添加偏好与背景信息；也可以点击任意消息下的操作，选择“记入记忆”，编辑后保存。所有对话共用这些记忆，新对话也可使用；每条可编辑或删除，支持清空与总开关。仅用户主动保存，不会自动提取聊天内容，不会让模型无提示修改记忆。

开关默认开启，初始没有任何记忆。启用且有条目时，聊天请求将记忆与助手设定合并成 system 消息，不受最近对话轮数裁剪；每次发出请求前固定记忆快照。关闭后保留本机条目，之后的请求不再携带这些记忆。已发送的内容无法从服务商处撤回。创作任务不携带长期记忆。单条最多 3000 字符，最多 100 条，总计最多 24000 字符。

记忆编辑与删除确认使用底部面板。删除聊天不会删除已保存记忆；清空应用数据或卸载会清除全部本机数据。

## 数据与密钥

API Key 使用 Android Keystore 中的 AES-GCM 密钥加密，配置与聊天记录保存在应用私有目录；聊天正文、附件、创作记录与缓存媒体不做额外加密。创作记录保存服务配置 ID、模型、描述、任务 ID 和本地结果，不复制 API Key；图片结果下载期间会临时缓存生成结果。长期记忆保存在应用私有目录的独立 memory.json 文件中，正文不额外加密。没有登录、广告或统计 SDK。

聊天请求发送到配置的服务地址，服务端会收到所选上下文、助手设定、已启用的长期记忆和 API Key。默认要求 HTTPS；确需 HTTP 时须在该服务配置中开启“允许 HTTP”，HTTP 传输本身没有加密。应用不会跟随重定向，避免把鉴权信息发往另一个地址。

应用内语音输入已移除，使用键盘输入文字。

应用被系统结束时，流式回复可能中断；已写入的内容会保留，流式内容约每两秒保存一次。卸载或清除应用数据会删除聊天与密钥，请自行保留需要的信息。Android 自动备份已关闭，避免恢复出无法解密的密钥配置。

## 当前边界

本版接入 **OpenAI 兼容 Chat Completions、Images generation 和 Videos 任务接口**，Responses 仅用于同步生图工具调用；不包含 Responses 聊天、异步 Responses 任务查询、原生 Anthropic Messages、联网工具、自动余额查询、Cherry Studio 数据导入或桌面端同步。中转站的余额接口没有统一规范，需要后续按具体服务接入。

应用中的 AI 回答来自联网 API，不在设备本地运行大模型。手表能否独立使用取决于能否安装该 APK，以及手表自身的 Wi-Fi / eSIM 网络。使用系统键盘输入文字。OPPO Watch 3 尚未做实机安装、布局和联网验证。

## 构建

在当前 Termux 环境中使用已有 Android 工具链：

```sh
cd ~/g-studio
sh build.sh
sh tests/check.sh
```

需要 `aapt2`、`javac`、`java`、`jar`、`keytool`、`zipalign`、`apksigner`、`python3`。默认 Android SDK jar 与 D8 jar 位于 `../pulse-player/tools`，也可以通过 `GSTUDIO_SDK_DIR` 指定包含 `android.jar`、`android-res.jar` 和 `r8.jar` 的目录。

这个项目已经生成自己的签名，原始签名材料保存在 `tools/g-studio.keystore` 和 `tools/signing-password`。继续发布覆盖更新时必须保留并使用它们；构建脚本会比对 `signing-certificate.sha256`，不匹配便停止。迁移工作目录时请私下备份这些文件，勿公开分享。源码 ZIP 不包含私钥和密码，也不包含通用 SDK 工具。

`tools/init-signing.sh` 仅用于全新项目首次初始化，检测到既有签名或指纹会拒绝覆盖。当前项目不要重新初始化签名。
